# knowledge-exchange(構想)

> **AI が読み込める「まとまった知見」を、閉じた相手どうしで交換し、同じ環境で自動評価する** ための
> ホストと発表形態の構想メモ。実装は無い。新しい仕組みの提案でもなく、既にある部品の組み合わせ方の検討である。

## 見立て

研究や開発の成果は、いまは学会発表・論文という「人が読む形」で流通している。
近いうちに、これとは別に、

- **AI がそのまま読み込める形**(手順・データ・検証の物差し・結果がひとまとまり)で知見を書き、
- **共通のサーバにアップロード**し、
- そこで **自動的に評価される**(再現できるか・主張と結果が合っているか)

という流通の形ができると考える。発表の場は「聴衆の前」から「評価環境の中」へ移る。

## 前提(この構想が置く条件)

| 前提 | 意味 |
|---|---|
| **共通鍵** | 交換する知見は、相手ごとに共有した鍵で暗号化する |
| **HDD 輸送** | ネットワークでなく物理媒体で運ぶ。経路での漏えいと、相手の確認を物理側に寄せる |
| **独立サーバ・同一環境** | 各参加者は自分の独立したサーバを持ち、評価は **同じ環境**(同じ OS・道具・版・刺激データ)で走らせる。環境が同じなので、結果の違いは知見の違いとして読める |
| **戦略上のパートナー限定** | 公開の場ではない。戦略上のパートナーどうしだけが交換できる |

## 「まとまった知見」の単位(案)

論文1本ではなく、次の束を1単位にする。

1. **主張**(何が言えるか)
2. **手順**(機械が実行できる形。刺激・入力データは固定し、ハッシュで同一性を示す)
3. **検証の物差し**(何が満たされれば主張が成り立つか。対照=「何もしない設定」で計器の床を先に示す)
4. **結果**(手順を回した出力と判定)
5. **経路**(試して捨てた案と、その理由)

評価環境は 2 と 3 を自分の側で回し直し、4 と一致するかを判定する。

## 自動評価が判定すること(案)

- **再現**:同じ環境で手順を回して、同じ結果が出るか
- **整合**:主張が結果から言える範囲に収まっているか(結果にない数字・言い過ぎを拾う)
- **対照**:計器の床が示されているか、主張する差が床より十分大きいか

新規性や価値の判定は自動にしない(人と相手の戦略が決める)。

## 未決

- 単位の書式(何で書くか・どこまで機械可読にするか)
- 「同一環境」をどう配るか(媒体ごと配る/環境の定義だけ配って各自が建てる)
- 鍵の管理と失効、媒体の受け渡しの記録
- 評価の結果を誰が見られるか(出した側だけ/両者)
